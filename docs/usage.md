# 使い方欄の固定仕様

基準は所有者が承認した usage-research-v2。調査日2026-11-26の保存済み `research-rules.json`、`research-analyze.py`、`research-backtest.py` を Node に移植し、追加の著者ルート C を組み込む。辞書と閾値の原本は `config/usage-rules.json`。`ruleVersion` を状態と選出項目へ記録する。調査は現在値を過去へ当てはめた参考試算であり、過去の朝に取得できたという証明ではない。

## 採用条件

| 条件 | 固定値 |
| --- | --- |
| 公開窓 | 実行時刻から7×24時間以内。未来・公開不明・更新日時しかない記事を除く |
| 日付のみ | UTC日付−14時間〜＋36時間の両端が公開窓内 |
| 本文 | 日本語は空白以外1,500文字以上、英語は400語以上。全本文またはフィード content が必要 |
| 内容 | AI語、実践者語、結果語、利用意図の見出しか規定距離内の一人称利用記述 |
| 構造 | pre 2個以上、または手順＋異なる操作語3種以上＋コード/画像/成果物リンク、または prompt語＋引用1個以上/画像2個以上 |
| 除外 | 翻訳を示す題名、GitHub/HN議論/YouTube自体を原記事にするもの |
| A | HB≥10、または対応する HN 投稿が points≥20 かつ comments≥3 |
| B | Zenn/Qiita の saves≥10、likes≥5、saves/max(likes,1)≥0.25 |
| C | Simon の entries feed の英語記事、800語以上、公開窓内、実践タグあり、除外タグなし |

C の実践タグは `coding-agents`、`ai-assisted-programming`、`vibe-coding`、`prompt-engineering`。除外タグは `llm-release`、`live-blog`。C は反応と本文構造を免除する。`/atom/everything/`、リンク紹介、著者名の文字列一致だけでは C としない。著者リスト変更には所有者の明示決定が必要。どのルートでも掲載済み URL を除く。欠損した反応値を0で補わない。

## 順位と枠

A→B→C、初合格観測の古い順、強度降順、公開日時の新しい順、正規化 URL の文字順。A の強度は max(HB/10, 有効 HN 点/20)、B は saves/10、C は0とする。C を末尾に加えるのは既存の A→B の順を維持する実装上の決定であり、調査で C の順位を実証したという意味ではない。強い主張を表す shift 語は診断用で、合否・順位には使わない。

日本語2件、英語1件を順番に確保してから全体順位で最大5件まで追加する。同一言語3件、掲載元2件、掲載元＋著者1件まで。Zenn/Qiita/note の掲載元はサービス、それ以外は原記事ホスト。著者が取得できなければホストを代用する。異媒体の同一人物までは同定しない。少数の日に条件を緩めない。

## 取得と公開データ

Zenn は承認済み12トピックを latest で公開窓の外までページングし、一覧いいね5以上か、はてな経由で見つかった候補の本文を読む。Qiita は `created:>=開始日 stocks:>=3` の一覧を1〜2回/日、100件/回までとし、個別 API を呼ばない。未認証60回/時の上限に対して十分小さい回数を固定する。

はてなは現在の IT と総合 RSS だけで候補を発見し、件数 API を40 URL以下に分ける。はてな系は5秒以上、同一ホストは直列で最低1秒を空ける。HN は `search_by_date` を日付で分割して取得し、実践語と反応条件で本文取得対象を絞る。本文取得上限は20件/日。Simon は entries Atom だけを取得する。DEV/HF community/Lobsters/GitHub/追加会社フィードを使い方の発見元にしない。

任意ブログ本文は robots を確認し、禁止・403・429・タイムアウト・サイズ上限・構造不明を欠損として扱う。禁止経路や有料本文を回避しない。ソースごとに `ok` / `missing` / `forbidden` / `truncated` を raw に残し、失敗を他欄へ波及させない。公開日時は原記事または feed published から取り、HN投稿日時やはてな登録日時を代用しない。別ホストの canonical を主張する転載は保留する。

raw は `kind: usage`、id、原題、URL、source/host、言語、著者、公開日時、反応とその観測日時、採用ルート、議論リンク、600文字以内の抜粋を持つ。本文全文は保存しない。議論は条件を満たした HN 投稿を優先し、それがなければ HB≥1 のはてな entry ページを使う。反応がない場合は議論ボタンを出さない。

## 状態と執筆の境界

pending と seen を分ける。候補の初発見・初合格・最終観測・本文 hash/特徴・ルール版を記録し、公開後7日まで再確認する。未再取得の候補を過去の反応だけで採用しない。過去 raw の selected URL と当日の他欄を先に seen へ登録する。14日を超える状態を削除し、更新日時や閾値到達で公開窓を延長しない。

URL は scheme/host を小文字にし、末尾 slash、fragment、`utm_*`、`fbclid`、`gclid`、`ref_src` を除く。その他の query は値とともにソートして残す。HN の異なる `?id=` は別URLになる。題名の類似だけでは統合しない。

本番は Collect sources ワークフローだけが usage 状態を書き込む。同一号の再実行は固定 raw を返す。raw と state のステージ保存が失敗したら以前の状態へ戻し、ワークフローで同じコミットに確定する。検証用の明示した独立 fixture 出力だけはその配下に状態を作れる。

執筆者は selected の全 id を日英両版の `articles` に `category: usage` として含める。日本語出典の日本語版見出しは原題そのまま、それ以外は忠実に翻訳する。抜粋のみから「誰が・何のAIで・何をし・どうなった」を帰属付きの2〜3文にする。革新的・画期的・revolutionary は使用しない。原題と字数が両立しなければ執筆者が勝手に落とさず理由を報告する。

表示は既存記事欄の後、ランキングの前。0件なら空欄を作らない。日英のタブ、source/date、存在する反応だけ、元記事・議論ボタンを表示する。

## 検証

`fixtures/usage/README.md` に縮約した保存レスポンスの由来と合成部分を記録する。fixture は実ニュースの全文複製ではなく、形式テスト用の最小見本。テストは閾値境界、特徴 regex、A/B/C、タグ、順位・枠、pending、seen 初期化、URL、議論リンク、取得失敗、描画、日英 validator を対象にする。外部接続・本番 Actions・実公開の成功とは区別する。
