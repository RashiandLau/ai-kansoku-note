# AI観測ノート 構成と実装方針

Node.js 22以上のESMで、固定ルールによる収集、文章だけの編集データ検証、静的HTML生成、通知送信を分離する。通知送信に限り既存のweb-push 3.6.7を使用する。今回の実装ではfixtures、ref、raw、state、dataを変更せず、実行時の一時ファイルもリポジトリ内に置く。ネットワーク接続、依存パッケージ追加、Gitの状態変更は実施しない。

- 収集: 05:17 JST（cron `17 20 * * *`）のActionsと手動起動が担当する。mainに当日のrawがあれば終了する。数時間の遅延も許容し、変更のpush後は通知日付なしで公開を明示起動する。
- 執筆: Dotから15:00と18:00 JSTにCodex cloud taskを開始し、インターネットアクセスはOFFにする。JSTの今日を確定し、チェックアウト済みのmainで最初に当日の日英dataを確認する。両方あれば「本日分は作成済み」、次に当日のrawがなければ「当日の raw がまだない」と報告し、どちらもPRを作らず終了する。rawがある場合に両言語を執筆し、収集は実行しない。Dotは作成済み・raw未着の終了を通知せず、失敗だけ通知する。
- PR検証: 変更を同じ日付の日本語・英語dataの通常ファイル2つだけに限定し、raw/state変更やsymlinkを拒否する。信頼済みベースのコードとrawを直接使って文章を検証し、ベースrawの欠落は失敗にする。候補rawの検証や収集の例外は設けない。API差分をイベント差分と照合し、検証済みHEADに固定してマージする。
- 公開: マージ後はmainを対象とした別のworkflow_dispatchを起動する。日本語と英語のindex・日付・archiveページを同じ設計で生成し、各版の欠稿時はraw見出しを表示する。
- 通知: 日付入力付きの公開成功後だけ日本語見出しをWeb Pushで送信する。購読コードは利用者が管理者へ渡してActions secretに登録する。公開鍵以外の鍵や購読情報はコミットしない。
- テスト: data2ファイル限定と信頼済みベースrawの使用、通常ファイルとsymlink拒否、英語執筆ルール、両言語レンダリング、通知のユーザー操作とサービスワーカー、偽送信器によるsecret処理を確認する。統合結果と未実施の確認は [verification.md](verification.md) に記録する。

raw.selectedは表示順のID配列。itemsはIDから記事への辞書。公開日がないCHANGELOGと日次ランキングでは取得時刻をpublishedに用い、その意味を記録する。同一CHANGELOG URLの複数バージョンは別記事として残す。HNの重複は公式・国内・ランキングの記事へ議論情報とtop指定を引き継ぐ。
